目標 (ユーザ確定 2026-09-13): CASF-2016 で **scoring R > 0.816 かつ ranking ρ > 0.735**
を **単一モデル**で。期限 2026-09-17。アンサンブルはどうしても必要になったときだけ。

現状の正直な出発点 (`benchmarks/.../results/tables/affinity_comparison_metrics.csv`):

| | scoring R | ranking ρ |
|---|---|---|
| GenScore | 0.816 | 0.735 |
| Ours 単一ヘッド (joint, kdki-mean) | 0.771 | 0.647 |

7月のアンサンブル 0.790/0.674 は主表には使わない。**埋める差は +0.045 / +0.088。**

## なぜ 7 月の「天井」を再挑戦するのか

7/18 の結論は「**トークナイザ固定下で** ρ 0.675 が天井」。その固定が 3 つ外れている。

1. トークナイザが `xzkjxu9q` (coord 0.1073) から `vq_e250_lig3` (0.1021) に変わった。
   MLM も `mlm_e250lig3` になり、事前学習の holdout が CASF-285 から
   `eval_holdout_pdbs.txt` の 9,329 件に広がっている。**e250 で親和性ヘッドは一度も
   学習されていない** (`variants.py` の e250 系アームは `heads=()`)。
2. ポーズ側で勝ったのは**ヘッドではなくデータと損失**だった (v2 6.5k → v8 21.9k で
   +2.8pt、ListNet で +3.6pt DP@1A)。親和性側はどちらも試していない。
   7月の "ranking loss 失敗" は別物 (UniProt 群・w=1.0・8.5k docs で暗記)。
3. **親和性の推論はフレーム平均を一度もしていない。** `RescoringConfig.n_frames` は
   あるが `AffinityConfig` には無い。

## 仮説と、それぞれが外れたと分かる条件

**H1 (フレーム平均, 再学習不要)。** ポケット正準フレームは量子化を通じて予測に
σ≈0.32 Å 相当のノイズを乗せる (ポーズ側の実測)。このノイズは複合体ごとに独立で
pK とは無相関なので、Pearson R と クラスタ内 Spearman ρ の**両方を減衰させる**。
k フレームの平均で σ/√k に落ちる。
→ **予測**: 既存ヘッドのまま n_frames 16 で R も ρ も上がる。
→ **外れ**: n_frames 1 と 16 の差が両指標とも +0.005 未満。その場合、量子化ノイズは
   親和性予測では律速でないと確定し、以後 TTA は使わない。

**H2 (e250 バックボーン)。** 再構成が良いトークナイザの表現は pK ともよく整合する。
→ **予測**: 同一コーパス・同一ヘッドで e250 が xzkjxu9q を両指標で上回る。
→ **外れ**: 差が ±0.01 以内。その場合 7 月の診断 (表現の親和性信号が本質的に弱い) が
   トークナイザ世代に依らないことの確認になり、H3/H4 に賭ける。

**H3 (回転拡張)。** 親和性コーパスは 1 複合体 1 文書 (8.5k) しかなく、ポーズヘッドの
438k docs と 50 倍違う。同じ複合体を k 個の向きで書けば docs は k 倍になり、かつ
H1 と同じフレーム依存性を**学習時に**潰せる。
→ **予測**: `--num-rotations 8` が 1 を両指標で上回る。
→ **外れ**: 上回らない。その場合データ量ではなくラベル数が律速。

**H4 (listwise)。** ranking power の定義は クラスタ内 Spearman そのもの。ポーズ側で
効いた ListNet を、タンパク質群 (`.grp`) の上で使う。7 月の失敗は 8.5k docs に 99M
encoder が暗記したこと。H3 で docs が 8 倍になっていれば条件が違う。
→ **予測**: ρ が上がる。
→ **外れ**: train/listwise が 0 に張り付く (=暗記) か ρ が下がる。

## 決めておくこと (結果を見てから選ばないため)

- **主表は単一ヘッド・1 checkpoint。** 選択は val 損失のみで行い、CASF は見ない。
- **比較の相手は GenScore 固定**、検定は scoring=Steiger / ranking=Wilcoxon、
  Holm 補正。これは `prolit_bench.stats` に既にある実装をそのまま使う。
- **報告する n_frames は 16 に固定**する (ポーズ側で飽和が確認されている値)。
  1 は対照、4 は「1/√k で落ちているか」を見る診断としてだけ回す。
  **3 点のうち最良を選んで報告することはしない。** 4 が 16 に勝っても 16 を報告する。
- H1 は既存ヘッドで測る。**H1 の結果で H2-H4 の計画は変えない。**
- 4 指標すべてが外れたら、「トークナイザを変えても親和性 ranking は届かない」を
  結果として報告する。表は出す。

## H4 (listwise) を今夜回さなかった理由 — 符号

`ComplexRescoreModule` の ListNet 項は `softmax(-label/τ)` を目標にする。ラベルが
RMSD なら「小さいほど良い」なので、softmax は**近ネイティブ側**に質量を置く =
top-1 が決まる場所に勾配が集中し、これがポーズ側で +3.6pt を出した理由そのもの。
**pK は大きいほど良い**ので、同じ式をそのまま当てると softmax は**最も弱い結合**に
質量を置く。順序の制約自体は対称なので学習は壊れないが、鋭くする場所が逆になる。
ranking power を狙うなら符号を分ける必要がある (`listwise_higher_is_better` 相当)。
既存のポーズヘッドを壊さない形で入れてから回す。

連鎖は `-hold_jid` で組んである。`--run-name` が checkpoint 先を固定するので、
評価ジョブは学習を待たずに投入でき、`prolit_bench.runs.resolve_scoring_head` が
実行時に最良 checkpoint を選ぶ。

## H5 (encoder 凍結) — 追加登録 (2026-09-13 08:05, **CASF の数字を見る前**)

rot-8 の学習ログを見て追加。**CASF 評価はまだ走っている最中で、値は見ていない。**

観測した事実だけ: 65,200 docs (8 回転 × 8,150 複合体) でも
`train/loss 0.034` 対 `val/loss 0.922` で、**最良 checkpoint が epoch 0**。
patience 4 で 5 epoch で打ち切られた。7 月に 8.5k docs で起きた暗記が、
docs を 8 倍にしても消えていない。

**H3 の前提が間違っていた。** 「docs が増えれば暗記しない」と書いたが、回転は
**同じ複合体の同じ pK** を 8 通りの向きで書くだけなので、**文書数は増えても
ラベル情報は増えない**。暗記を防ぐのは独立なラベルであって文書数ではない。
回転拡張が効くとすればフレーム頑健性の経路 (H1 を学習時に入れる) であって、
過学習の経路ではない。H3 はその狭い意味でのみ評価する。

**H5**: 暗記しているのは 99M の encoder なので、凍結して 0.59M のヘッドだけ
学習すれば、表現から線形に取れる分だけが出る。
7 月に凍結は試して失敗しているが、**あれは ranking loss と同時に入れた**ので
どちらが効いたか分離できていない。ここでは損失は素の回帰のままにする。

→ **予測**: val/loss の最良が epoch 0 より後ろに動く (暗記が止まった証拠)。
   CASF は fine-tune 版と同等以上。
→ **外れ**: val 最良が依然 epoch 0、または CASF が明確に下がる。その場合
   「表現から線形に取れる分 < fine-tune で取れる分」で、暗記は害でなく
   必要経費だったことになる。
→ どちらでも `docs/results/` に書く。

投入: `afffrz` (gpu_1, 12h) → `afffrzeval` (gpu_1, 2h)。rot-8 コーパス上、
`--freeze-encoder` 以外は `afftrain_rot-8` と同一。

## H7 の設計欠陥と訂正 (2026-09-13, 数字を見る前)

**和集合コーパスの val が 60% 汚染されていた。** 投入前に「PDBbind の学習側を
BioLIP の val タンパク質で濾していないので、この腕の val は checkpoint 選択の分だけ
楽観的」と書いたが、**「分だけ」で済む量ではなかった**。実測:

- BioLIP の val = 72 タンパク質群 / 432 pdb
- そのうち **258 pdb (59.7%) が PDBbind の Kd/Ki 集合にある** → 和集合の学習側に入る
- 結果: val loss が 0.84 → 0.49、早期終了が epoch 1-4 → 9-10

**気づいた経路**: val loss の落ち方が大きすぎた。最初にトークン列の完全一致で
leak を探したが 0 件だった — が、これは検査として厳しすぎる。**同じ PDB でも
BioLIP の receptor/ligand ファイルと PDBbind の protein.pdb/ligand.sdf では
ポケットの切り出しも原子順も座標も違うので、トークン列は一致しない。**
pdb id の水準で照合し直して確定した。

**CASF は汚染されていない** (両コーパスとも `eval_holdout_pdbs.txt` を除外)。
つまり実行中の 3 本の評価は**正しい測定**だが、**選ばれた checkpoint が悪い**。
H7 の判定には使えない。

**訂正**: `data/affinity_union_holdout_pdbs.txt` (eval-holdout 9,329 ∪ BioLIP val 432
= 9,761 pdb) を除外リストにして PDBbind を再トークン化 (job 8657668)、和集合を
作り直して 3 seed で回す。`variants.py` の `SEED_FAMILIES` から汚染腕を外し、
clean 腕を入れた。

**教訓**: 2 つのコーパスを足すとき、**片方の val が他方の train に入っていないか**は
必ず id 水準で確かめる。トークン列の一致では見つからない。

## clean 版 H7 の読み方 — 先に決めておく (2026-09-13, 数字が出る前)

汚染版が **R 0.8072 ± 0.0054 / ρ 0.6649 ± 0.0064**、rot1 が
**R 0.7544 ± 0.0505 / ρ 0.6953 ± 0.0431** という形だった。
clean 版が同じ形に出たとき、後から理由を作らないために先に書く。

**判定は対比較の `n_better` で行う** (3 seed では p 値にほとんど検出力が無い)。
`scoring_n_better` / `ranking_n_better` が 3/3 でなければ「効いた」と言わない。

想定される 3 つの結果と、それぞれで何を結論するか:

1. **R も ρ も 3/3 で上** → H7 成立。和集合を主系統にする。
2. **R が 3/3 で上、ρ が 3/3 で下** (汚染版と同じ形) → **「ラベルを増やすと
   大域較正は良くなるがクラスタ内識別は悪くなる」**という交換として報告する。
   原因の候補は 2 つあり、**どちらかを後から選ばない**:
   (a) 2 つのソースが同じタンパク質に別の測定系のラベルを付けており、
       クラスタ内の順序が混ざる (PDBbind pK 中央値 6.18 対 BioLIP 6.54)、
   (b) 単にデータ量が大域相関を助けるだけで、ρ とは無関係。
   分けるには **PDBbind 単独** 3 seed が要る。**その腕を先に回してから**原因を書く。
3. **どちらも 3/3 でない** → H7 も外れ。**制約内のレバーは尽きた**と結論し、
   「トークナイザを変えない限り GenScore の両指標超えには届かない」を結果として
   報告する。表は出す。

**分散について**: 汚染版で union の seed sd が 8 倍小さかった。clean 版でも残るなら
それ自体が成果 ([[feedback_single_run_comparisons]] の 3 seed コストが下がる)。
**残らなければ、あれは leak が全 seed を同じ遅い epoch に寄せた産物**だったと結論する。
平均が動かなくても分散は別に報告する。

## H7 clean 版のコーパス素性 — 読む前に記録 (数字が出る前)

`affprep` (8657765) が通ったので、実際に何が出来たかを確認した。

| コーパス | train docs | val | max_len |
|---|---|---|---|
| `e250aff_r1` (対照) | 8,150 | 431 (共通) | 509 |
| `e250aff_union_clean` | 15,509 | 431 (共通) | 526 |
| `e250aff_pdbbind_clean` | 7,359 | 431 (共通) | 526 |

除外リストは効いている: PDBbind の複合体が 7,993 → 7,734 (**259 件減**)。
これは BioLIP val の 432 pdb のうち PDBbind 側にあった分で、事前の見積り 258 と一致。
val は 3 コーパスで同一 (prep のガードが byte 比較で確認済み)。

### 文書数 +90% と「独立ラベル +54%」は矛盾しない

| | |
|---|---|
| 文書数 | 8,150 → 15,509 (**+90%**) |
| **unique な複合体** | 8,528 → 13,098 (**+54%**) |
| 両ソースに重複 | **3,960 件 (unique の 30%)** |

投入時に「独立ラベル +54%」と書いたのは**正しい**。文書は +90% 増えるが、
うち 3,960 件は**同じ複合体を 2 通りのポケット切り出しで書いたもの**である。

### 重複のラベルはほぼ一致する (が、尾がある)

重複 3,960 件の pK 差:

| | |
|---|---|
| 中央値 \|Δ\| | **0.003** |
| 90 パーセンタイル | 0.036 |
| \|Δ\| > 1.0 | **3.8%** (~150 件) |
| \|Δ\| > 2.0 | 1.6% |
| 最大 | 7.09 |

**大半は実質同一ラベル**なので、重複は穏やかな augmentation として働く
(同じ複合体・同じラベル・違う切り出し)。

**ただし ~150 件は矛盾するラベルを 2 つ持つ。**
このノイズは **union 腕にだけ入り、rot1 対照には入らない** ——
腕間の非対称なので、H7 の結果をどちらの方向にも動かしうる。

### したがって H7 の読み方に条件を足す

- **union が勝った場合**: 「独立ラベルが効いた」と「重複 augmentation が効いた」を
  この 2 腕では分離できない。**PDBbind 単独腕 (同時に走っている) が切り分けになる**:
  PDBbind 単独は重複を持たないので、そこでも上がるならラベル量の効果。
- **union が負けた場合**: ~150 件の矛盾ラベルが原因かどうかは、
  **矛盾を除いた第 3 の腕を作らないと言えない**。今夜は作らない。
  「負けた」としか書かず、原因は未特定として残す。
- どちらにせよ **CASF は無傷** (両コーパスとも eval holdout を除外済み) なので、
  評価そのものは汚染されていない。

## H8 / H9 — 追加登録 (2026-09-13 深夜、H7 の結果を見た後)

H7 は成立しなかった (scoring 2/3、ranking 1/3) が、**seed 平均予測**で見ると
union は **R 0.8074 / ρ 0.7105** (GenScore 0.8159 / 0.7351) で、
**scoring は残り 0.009**。かつ union は **scoring の分散だけ潰した**
(sd 0.0030) が **ranking の分散は残っている** (sd 0.0232)。
平均化で ρ が +0.048 上がるのに R は +0.018 しか上がらないのはそのため。

### H8: 矛盾ラベルが union の ranking を壊している

**根拠**: ranking power は**タンパク質クラスタ内**の Spearman である。
BioLIP と PDBbind が同じ pdb に **|Δ|>1.0 log の矛盾ラベル**を与えている複合体が
**151 件** (平均差 2.08、最大 7.09)。同一タンパク質内に矛盾する順序を教えるので、
**ρ が測るまさにその場所を壊す**。scoring (大域相関) への影響は相対的に小さいはず。

→ **予測**: 151 件を除いた `union_noconf` は、union に対し
   **ranking が上がり、scoring は下がらない**。
→ **外れ**: ranking が上がらない。その場合、union の ranking 低下は
   矛盾ラベルのせいではなく、PDBbind データの ranking 品質そのもの
   (単独で ρ 0.6345) が混合物に漏れているため、と確定する。
→ 判定は `n_better`/3、対照は `e250_union_clean` (対照が変わることに注意。
   H7 の対照は rot1 だった)。

### H9: 安定したコーパスの上なら listwise が効くか

**根拠**: ranking が最も遠い指標 (union 0.663 対 GenScore 0.735) で、
ranking を直接最適化する損失は ListNet である。
7 月と本日の H4 で listwise は失敗しているが、**どちらも rot1 級の小さく
不安定なコーパス上**だった (R sd 0.05)。union は 2 倍のデータで
**scoring 分散が 17 倍小さい**。条件が違う。符号も修正済み
(`--listwise-higher-is-better`)。

→ **予測**: ranking が上がる。
→ **外れ**: 上がらない、または `train/list` が下限付近に張り付く。
   その場合 **listwise は 3 度目の失敗**となり、この系統は打ち止めとする。
→ **既知の限界**: union_clean の PDBbind 側は `.grp` を持たないので
   `mix.py` が**シングルトン群**を与えている。つまり**ランキング対を出すのは
