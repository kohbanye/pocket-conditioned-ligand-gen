# ずれの正体はアンカーのばらつき (2026-08-23)

独立な 4 つの測定が同じ機構を指した。

## 1. 生成分子はポケットの外ではなく、隣に座っている

参照リガンドを基準に、生成分子がどこにいるか (99 標的):

| | ProLIT | FLOWR | 参照 |
|---|---|---|---|
| 参照重心からの距離 | **2.100** | 0.906 | - |
| 参照の占有領域と重なる割合 | 0.700 | 0.909 | - |
| 分子の広がり (A) | 3.533 | 3.497 | 3.479 |
| 衝突数 (中央) | 0.000 | 0.000 | - |
| 受容体と接触する原子の割合 | 1.000 | 1.000 | - |

**サイズも形も正しく、衝突もゼロで、受容体に触れてもいる。**
ただ 2.1 A 隣の、立体的には問題ないが間違った場所にいる。

## 2. それは系統誤差ではなく、ばらつき

同じ標的の生成分子どうしで、重心のずれを系統成分とばらつき成分に分ける:

| | ProLIT | FLOWR |
|---|---|---|
| 重心ずれ RMS (A) | 2.607 | 1.020 |
| 系統成分 | 1.108 (**21%**) | 0.776 (**67%**) |
| ばらつき成分 | **2.241** | 0.548 |
| 60 分子中の最良 | **0.467** | 0.269 |

**結合部位を取り違えているのではなく、定まっていない。** FLOWR は逆で、
場所は決まっていて (系統 67%)、ばらつきが小さい。

そして**生成物の中には十分よく置けたものが存在する** (最良 0.467 A)。

## 3. ばらつきはアンカーから来る

生成 SDF の原子順は生成順なので、原子 0 が「最初に置いた原子」:

| | 広がり (A) |
|---|---|
| 最初の原子 (原子 0) | **2.808** |
| 重心 | 2.201 |
| 最後の原子 | 5.206 |

**比 (重心/最初の原子) = 0.840、Spearman = +0.738 (p=2e-18)。**
アンカーのばらつきの 84% がそのまま分子全体のばらつきになる。

## 4. teacher forcing のアンカー誤差と一致する

正しいポケットを与えた teacher forcing で、最初の原子の誤差は **2.13 A**
(別標的のポケットなら 3.02、ポケット無しなら 3.54)。
これは 1 の「参照重心からの距離 2.10 A」とほぼ一致する。

**機構: アンカーが 2.1 A ずれ、その周りに分子が整合的に組み上がるので、
分子全体が 2.1 A ずれる。**

## 打ち手: アンカーだけ冷たくサンプルする

`--anchor-temperature` / `--anchor-atoms` を実装した
(`scripts/generate_ligands_for_target.py` の `_AnchorTemperature`)。
`generate` は系列全体に 1 つの温度しか持たないので、warper の手前で
logits を定数倍して実効温度を変える。

後続の原子は元の温度のままなので、**分子の多様性は保ったまま
配置のばらつきだけを削れる**。0.3 / 0.5 / 0.7 を掃引中 (job genanch)。

ただし上限はある。argmax (実効温度 0) でもアンカー誤差は 2.13 A なので、
ばらつきを消しても系統誤差 2.13 A は残る。現在の RMS 2.607 に対して
**期待できるのは 2.607 -> 2.1 程度**。ポーズ精度曲線に載せると
1 kcal/mol 前後。

## 選別では取れなかった (幾何) / 少し取れた (rescorer)

生成物の中に良いものがあるなら選別できるはず、という筋:

| 選別基準 | score |
|---|---|
| 選別なし | -1.85 |
| 衝突数 | -1.75 |
| PoseBusters | -1.77 |
| ポケット重心からの距離 | -1.84 |
| **ProLIT rescorer 上位 10%** | **-2.28** |
| (参考・不公平) Vina 上位 25% | -3.41 |

**幾何は 3 つとも効かない** (ポケット重心との相関は +0.064)。
論文自身の rescorer (`head_e10_lw1.0_s7`, ListNet) だけが効き、
標的内 Spearman(head, vina_score) = -0.210 (符号は正しい向き)。
上位 10% で **+0.43 kcal/mol**。ただし 10 倍生成するコストがかかる。

Vina で選ぶ上限が -3.41 なので、選別で取れる分はまだ残っている。
**良し悪しを決めているのは単純な幾何ではなく、スコア関数の領分。**

## アンカー温度は効くが、最初の測定は 2.5 倍に盛れていた (訂正)

> **訂正**: 下の表は**後処理済みの基準** (`gen100_arom_post`) と
> **未処理のアンカー** (`gen_anchor_*`) を比べていて、成立しない。
> 後処理 (`relax_generated.py --torsions`) は clash-free を
> 0.655 -> 0.979 に上げる代わりに、衝突を逃がすために分子を押しのけて
> 参照からの距離を 1.67 -> 1.93 A **悪化**させる。その差分を丸ごと
> アンカー温度の効果として計上していた。正しい値は次節。

## アンカー温度は狙い通り効いた (幾何) -- 撤回した測定

`--anchor-temperature` で先頭 3 トークンだけ温度を下げた。50 標的:

| | 原子0 広がり | 重心 広がり | 参照からの距離 | ユニーク率 | 原子数 |
|---|---|---|---|---|---|
| t=1.0 (現行) | 2.786 | 2.139 | 2.028 | 0.578 | 22 |
| anchor=0.7 | 2.309 | 1.730 | **1.731** | **0.593** | 23 |
| anchor=0.5 | 2.234 | 1.721 | **1.703** | 0.568 | 22 |
| anchor=0.3 | 2.096 | 1.687 | 1.722 | 0.554 | 23 |

アンカーの広がり -25%、重心の広がり -21%、**参照からの距離 -16%**。
**ユニーク率も分子サイズも落ちていない** (0.7 ではむしろ上がる)。
狙い通り、多様性を保ったまま配置のばらつきだけ削れている。

0.5 と 0.7 の差は小さく、0.3 まで下げても距離は改善しない
(1.703 -> 1.722)。**アンカー誤差の系統成分 2.13 A が下限**という予測と
整合する。Vina は測定中 (job evanch)。

## アンカー温度の正しい効果 (すべて後処理前、100 標的)

| | 原子0 広がり | 重心 広がり | 参照からの距離 | ユニーク率 |
|---|---|---|---|---|
| t=1.0 (基準) | 2.374 | 1.879 | 1.863 | 0.602 |
| anchor=0.7 | 2.302 | 1.848 | **1.762** | 0.583 |
| anchor=0.5 | 2.247 | 1.814 | 1.806 | 0.565 |
| anchor=0.3 | **2.114** | **1.716** | **1.743** | 0.554 |

| | 撤回した値 | 正しい値 |
|---|---|---|
| 原子0 広がりの減少 | 25% | **11%** |
| 重心 広がりの減少 | 21% | **9%** |
| 参照からの距離の改善 | 16% | **6%** |

**機構は実在するが、効果は小さい。** ポーズ精度曲線に載せると
1.863 -> 1.743 A は 0.2-0.3 kcal/mol 程度。ユニーク率も 0.602 -> 0.554 と
下がるので、ただで手に入るわけでもない。

これは「argmax でもアンカー誤差 2.13 A は残る」という予測とも整合する:
**削れるのはばらつきだけで、それはずれ全体の一部でしかない。**

### 教訓

`_post` が付いた tree と付いていない tree を比べない。後処理は
clash と配置を**逆向きに**動かすので、片方だけにかけると効果の符号すら
変わりうる。比較は必ず同じ後処理段階どうしで行う。

## 見込みと、残る差

| | score |
|---|---|
| 現行 | -1.89 |
| + rescorer 上位 10% | -2.28 (実測) |
| + アンカー温度 | ~-2.9 (見込み) |
| **FLOWR (同一評価器)** | **-5.63** |
| 参照分子・VQ 往復 + refiner = 天井 | -5.86 |

**両方効かせても 2 kcal/mol 以上残る。** 天井 (-5.86) は FLOWR より上なので
到達可能性は残っているが、それには**アンカー誤差 2.13 A 自体**を
下げる必要がある。ポケット除去実験が示したとおり、CLM は別標的の
ポケットを与えられても 0.65 -> 1.04 A しか悪化しない = ポケットを
弱くしか使っていない。

残る未検証の手は `--pocket-dropout` + classifier-free guidance
(job clmcfgp、gpu_1 パイロット)。これが診断した根本原因を直接叩く唯一の
残り手。

## アンカー温度は却下 (公平に比べると効果なし)

75 標的、**どちらも `relax_generated --torsions` 済み**:

| | PB | clash-free | score | min | dock |
|---|---|---|---|---|---|
| t=1.0 (基準) | 0.921 | 0.966 | -1.73 | -4.41 | -7.09 |
| anchor=0.5 | **0.930** | 0.968 | -1.73 | -4.45 | -7.11 |

標的中央値で対応をとると:

| | 基準 -> anchor | 中央差 | 改善標的 | p |
|---|---|---|---|---|
| score | -1.89 -> -1.88 | -0.03 | 57% | 0.39 |
| min | -4.50 -> -4.55 | -0.03 | 52% | 0.58 |
| dock | -7.13 -> -7.20 | -0.02 | 61% | 0.06 |

**どれも有意でない。** 一度は「score -1.85 -> -2.64」と報告したが、
それは後処理済みの基準と未処理のアンカーを比べた産物だった。
幾何で見た変位の減少が 6% しかなかったことと整合する
(6% では Vina は動かない)。

**アンカー温度は却下。** 機構 (アンカーのばらつきが分子全体に伝播する) は
実在するが、温度を下げて削れるのはばらつきだけで、ずれの本体である
系統誤差 2.13 A には届かない。
