`pipelines/train/vqvae.py` には `--freeze-encoder` と `--init-from` が
**実装済み**で、docstring にも

**それでもこのセッションでは一度も実行していなかった。**

`--freeze-encoder` は 1 コマンドで回せるのに手を付けていなかった。
優先順位付けの誤り。

## 素直な再学習では効かない（測定から）

配備 VQ の**往復**は bond MAE 0.042 A で、**多様体上ではデコーダは正常**。
問題は多様体**外**（生成されたコード列）:

| | 結合が許容外 |
|---|---|
| AR のコード列を decode | 9.8% |
| **cold のコード列を decode** | **30.0%** |

同じデータで再収束させても同じ場所に戻るだけ。

## 実行した版: 幾何損失を重くしたデコーダ単独再学習

```
--init-from <配備 VQ> --freeze-encoder
--weight bond12={20,60} --weight clash=15 --max-epochs 30
```

**狙い**: 「座標を当てる」より「**化学的に妥当な結合長を出す**」を優先する
デコーダにする。多様体外の入力に対しても、
壊れた分子ではなく妥当な分子を出すようになるはず。

`--freeze-encoder` なので **codes は動かず、既存の LM / MLM checkpoint と
トークン列はすべて有効なまま**。

**判定**: 生成 + Vina + PB。特に
**AR / cold 双方のコード列を decode したときの結合長**を見る
（9.8% / 30.0% が下がるか）。

## 位置づけの修正（著者の指摘を受けて）

**デコーダだけ差し替えた構成を論文に出すと「なぜそこだけ？」と問われ、
正直に答えると「Vina を良くするため」になる。指標に合わせて部品を調整した、
と読まれる形。** これは避ける。

| | 役割 |
|---|---|
| **デコーダ単独（`decgeom`）** | **パイロット**。損失変更が効くかを ~4 pt で見る |
| **VQ-VAE 全体再学習** | **本番の検証**。論文に出すのはこちら |

### 損失変更は Vina と独立に正当化できる

上げている項は **Vina の項ではなく化学の項**:

- `bond12` — 結合長。分子内の化学
- `clash` — config のとおり**リガンド行のみ** = 分子内の重なり

どちらも**タンパク質にもスコア関数にも言及しない**。動機はこう書ける:

| | 結合が許容外 |
|---|---|
| 結晶リガンド | **4.5%** |
| FLOWR | 4.4% |
| **ProLIT のデコーダ出力** | **48.1%** |

**「デコーダが化学的に妥当でない幾何を出す」は Vina を参照せずに言える欠陥。**
物理的妥当性の項を重くするのはその修正であって、
**Vina の改善は結果であって目的ではない。**

### 判定の主従を入れ替える

- **主要**: PoseBusters validity、結合長の許容外率（化学）
- **副次**: Vina score / min / dock
- **制約**: 往復の天井 (-5.60) が下がらないこと（表現力を犠牲にしていない担保）

## 予測

- **bond12 を上げれば結合長は良くなる**（直接その項なので当然）
- **問題は coord とのトレードオフ**。座標精度が落ちれば往復の Vina 天井
  (-5.60) が下がり、LM 側の伸びしろが減る
- b=20 と b=60 の 2 点でその曲線を見る

**天井 (-5.60) が下がるなら採用しない。** 化学を買って表現力を失う取引は、
このセッションで何度も棄却してきたのと同じ形。

## パイロットの初期結果（epoch 11/30、**暫定**）

| | 往復 RMSD | 往復の結合 >0.15A | **コード 10% 摂動後** |
|---|---|---|---|
| 配備 VQ | 0.363 A | **3.3%** | **26.4%** |
| b=20 | 0.380 A | 4.4% | 23.9% |
| b=60 | 0.385 A | 4.6% | **21.8%** |

- **狙った多様体外は改善**（26.4% -> 21.8%、相対 17%）だが**幅が小さい**
- **多様体上は悪化**: 往復 RMSD 0.363 -> 0.385（6%）、
  結合 3.3% -> 4.6%（**bond 損失を重くしたのに往復の結合が悪化**）

### 逆転の説明候補（未検証）

1. `--loss-balancing constrained` が重みを再正規化しており、
   raw の重みを上げた効果が想定と違う
2. 収束済み checkpoint の損失を変えたことで一度崩れ、
   11 エポックではまだ再収束していない

**2 なら残り 19 エポックで戻る**ので、ここで結論は出さない。
（このセッションで epoch 0-1 の判断を 2 回外している。）

ただし `val/atom_coord` は 0.1022 -> 0.1186 と単調に悪化しており、
これは損失変更の直接の帰結。**天井は下がる方向**と見ている。

### 現時点の見込み

判定規則（**天井が下がるなら採用しない**）に照らすと厳しい。
効果 17% に対し、往復 RMSD 6% 悪化・on-manifold 結合 1.3 pt 悪化は割に合わない。

**この場合の結論は「損失の重み付けでは直らない」**であって、
VQ 全体再学習に進む根拠にもならない（同じ損失を全体に適用しても
同じトレードオフが出るはず）。パイロットが 4 pt でそれを示せるなら、
78 pt を節約したことになる。

## 確定（再収束後、摂動シードを固定）

| 摂動シード | 配備 | b=20 | **b=60** |
|---|---|---|---|
| 0 | 27.7% | 26.1% | **24.4%** |
| 1 | 21.1% | 20.7% | **19.7%** |
| 2 | 26.3% | 24.0% | **23.1%** |
| **平均** | **25.0%** | 23.6% | **22.4%** |

**3 シードすべてで 配備 > b=20 > b=60 の順序が一貫 = 用量反応がある。**

| | 効果 / 代償 |
|---|---|
| 多様体外の結合（狙い） | **25.0% -> 22.4%**（相対 10% 改善） |
| 往復 RMSD（代償） | 0.363 -> 0.381 A（5% 悪化） |
| 往復の結合（on-manifold） | 3.3% -> 3.3%（**不変**） |

### 訂正: 「用量反応が無いのでノイズ」は測定不備だった

摂動の乱数を固定していなかった（`torch.rand` を seed していない）ため、
**同じ checkpoint が 26.4% と 28.5% を出していた**。
その状態で b=60 が b=20 より悪く見えたのを「用量反応が無い」と読んだ。

**同じ checkpoint で 2 ポイント動いている時点で気づくべきだった。**
シードを固定して同じ腐敗を全 checkpoint に当てたら、順序は一貫した。

### 判定は生成 + Vina + PB へ

効果も代償も小さく、これだけでは決められない。
`gen_dec60_ml`: **同じ LM コードを別デコーダで復元するだけ**なので、
デコーダ以外は完全に同一のクリーンな比較。

主要指標は PB と結合長、副次が Vina（著者の指摘による位置づけ）。

## 生成では効果ゼロ（2026-08-30 13:45）

同じ 60 標的、**LM も refiner も同一、デコーダだけ違う**:

| 構成 | 結合長誤差 | >0.15A |
|---|---|---|
| 配備デコーダ + press0.6 | -0.118 | **48.1%** |
| 再学習デコーダ b=60 + press0.6 | -0.122 | **48.9%** |
| FLOWR / 結晶 | -0.020 | 4.5% |

**合成のコード摂動では相対 10% 改善したのに、実際の生成では何も変わらない。**

### なぜ転移しなかったか

1. **この構成では refiner が支配的**。デコーダの出力（refiner 無しなら 9.8%）を
   refiner が 48% まで壊す。デコーダを良くしても後段で壊れる
2. **合成の 10% ランダム摂動が、LM が実際に出すコード列を代表していない**

2 は自分で作った代理指標の妥当性の問題で、
このセッションで「割合の代理は二乗で効く量の代理にならない」と学んだのと同じ形。
**代理で測った改善は、本番で測るまで改善ではない。**

### パイロットの結論

**損失の重み付けによるデコーダ再学習は、配備構成では効果が無い。**
したがって **VQ 全体再学習（~78 pt）に進む根拠にならない。**

**パイロット 4 pt が 78 pt を止めた。** これが「デコーダ単独＝パイロット、
全体＝本番」という位置づけの正しい使い方（著者の指摘による）。

`gen_dec60nr_ml`（refiner 無し）でデコーダ単独の寄与も確認する。

## 決着 (2026-08-30, evdec60 8/8)

配備リファイナ (press0.6) 込みの生成、100 標的ペア Wilcoxon:

| | 配備デコーダ | 再学習 b=60 | delta | p |
|---|---|---|---|---|
| vina score | −1.10 | −0.95 | +0.00 | 0.781 |
| vina min | −4.67 | −4.74 | −0.02 | 0.260 |
| vina dock | −7.32 | −7.33 | −0.00 | 0.214 |
| pb_valid | 0.00 | 0.00 | — | — |
| strain | 769 | 828 | — | — |

**Vina は 3 指標とも動かない。**

一方リファイナを外すと結合逸脱は 8.1% → 6.1% (p=1.8e-13) と確かに改善している。
つまり **再学習は効いているが、後段のリファイナが完全に消している。**

**結論**: 損失の重み付けによるデコーダ再学習は、配備構成では Vina に効果が無い。
効果があるのはリファイナを外したときだけで、その大きさはリファイナの破壊の 1/23。
→ **VQ 全体再学習 (~78 pt) の根拠にならない。パイロット 4 pt が 78 pt を止めた。**

そして本当の含意は別のところにある: **デコーダは既に十分で、壊しているのはリファイナ。**
