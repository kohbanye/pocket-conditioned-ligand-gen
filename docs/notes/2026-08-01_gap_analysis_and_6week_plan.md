## 3. 分析フェーズの設計

**目的は「弱点を確認すること」ではなく「弱点を洗い出すこと」。**
以下の軸を全部通す。特定の仮説を検証しに行かない。

### 軸 A — 段階分解

同一の複合体集合に対し、**各段の出力で同じ指標を全部測る**。
どこで何が失われるかを、想定せずに全段から取る。

```
結晶 → descriptor 往復（量子化なし）→ VQ 往復（量子化あり）
     → LM 生成 → refiner → 緩和 → 分子として組み立てた後
```

### 軸 B — 指標を絞らない

各段で以下を全部取る。事前に「これが効いているはず」で間引かない。

- **幾何**: per-atom RMSD / Kabsch / 結合長 / 結合角 / 二面角 / 環の平面性 / 内部 clash / 対タンパク clash
- **化学**: element・charge・hybrid・aromatic・ring・numH の一致率 / 価数 / sanitize 可否 /
  断片数 / 芳香環数 / 結合次数の分布
- **界面**: lDDT-PLI / Contact-F1 / 接触数 / 最近接距離
- **実用**: PoseBusters の**サブチェック個別**（総合の PB-valid でまとめない） /
  Vina 3 モード / QED / SA / strain
- **コスト**: bits/atom / トークン数 / 復元対象原子数

### 軸 C — 層別

上の指標を、以下の切り口で全部切る。平均だけを見ない。

リガンドサイズ / 元素 / 環内・環外・環サイズ / 回転可能結合数 / protein vs ligand /
backbone vs side chain / 残基種 / ポケットサイズ / 標的 / コードの使用頻度 /
protein-ligand 共有コード vs 専有コード

### 軸 D — 分布と最悪ケース

平均だけでなく分位点と裾を見る。**最悪 N 件は実物を書き出して目視する**
（`outputs/reconstruction_pdbs_worst*` に既に仕組みがある）。
指標に出ない壊れ方を拾うのはここだけ。

### 軸 E — 対応付きの比較

joint vs separate、Ours vs 各ベースラインを**同一アイテムで paired に**比較し、
勝ち負けの標的リスト・分子リストを出す。集計値の差だけを見ない。

### 軸 F — 未測定の洗い出し

上を通したうえで「まだ一度も測っていないもの」を列挙する。
現時点で分かっているだけでも: 量子化**前**の連続 latent からのデコード精度、
主系統の既定ハイパラでの 100 標的値、ESM3 のポケット入力条件、
DP を外している標的の性質、best-of-56 の選択バイアス量。

### 成果物

1. **段 × 層 × 指標のテーブル**（コードから再生成できる形で）
2. **最悪ケース集**（実物 + 目視所見）
3. **見つかった弱点のリスト**（優先度も原因も、この時点では付けない）

**ここまで出てから改善計画を引く。** 今の時点で方向を決めると、
下の「既に立ててしまった仮説」に引きずられる。

### 既に立ててしまった仮説（アンカーしないこと）

記録としては残すが、**これらを確認しに行く形で分析を組まない**。
コードから読める事実は、`source` フラグがエンコーダ入力専用でデコーダに渡っていないこと、
8192 コード中 5795 が protein/ligand で共有されていること、再構成損失が per-atom 絶対座標
MSE のみであること、`ATOM_LAYOUT` に結合次数が無いこと。
**これらが観測されている症状の原因かどうかは未検証**であり、
他により大きい要因がある可能性を潰していない。

## 4. 原則

1. **最初は仮説を置かずに広く測る。** 想定した弱点だけを確認しに行くと、それしか出てこない。
   優先度付けは弱点が出そろってから。

2. **測定は最小単位で分ける。** VQ 往復 / LM 生成 / 組み立て / 緩和 を混ぜて測らない。
   混ぜた指標は改善を帰属できず、次の一手を決められない。

3. **学習不要 / forward のみの測定を先に。** 数時間で済み、最も高価な意思決定
   （トークナイザを作り直すかどうか）に効く。

4. **診断に test を使わない。** 生成はチューニング用ポケット集合、リスコアリングは
   検証集合で診断する。F3 は診断に CASF を使ってしまった実例。

5. **公平性の穴は改善より先に塞ぐ。** 土台が動くと過去の測定が全部無効になる。

6. **V1 の重みと `normalization_stats.pt` は消さない。** 比較対象と fallback を失うと引き返せない。

7. **1 世代の作り直しは 1 回しか回せない。** VQ 単体なら 16h だが、再トークン化から
   下流まで含めると 1 チェーン数日〜1 週間。だから賭けの本数を減らす。

8. **コード準拠で進める。結果ディレクトリを増やさない。**
   コードは整理済みだが結果側は散らかっており、F7 と F10 はどちらもそれが原因で起きた。
   分析フェーズは dump が増えるので、同じことを繰り返さない。

   - 数値の置き場は `benchmarks/<bench>/results/<task>/<arm>/` だけ。
     `outputs/casf/` のような一時 dump を新設しない（`head_*.csv` 56 本、
     `pose_scores_ens*.csv` 17 本が溜まり、どれが論文の数値か追えなくなっている）。
   - 表は手で書かない。`make_tables.py` と `notebooks/paper_*.py` が唯一の出所。
   - 腕の同定は `variants.py` を通す。ディレクトリ名で腕を表現しない。
   - 探索の枝番（`_v8` `_s2b` 等）は run ディレクトリの `run.json` にだけ残す。
   - 分析スクリプトも規約どおりの場所へ。使い捨ては scratchpad に置き、リポジトリに入れない。

9. **主表は「単一モデル・既定ハイパラ」で出す。モデルの実力で示す。**
   査読で「その数値はチューニングとアンサンブルで作ったのでは」と言われる余地を構造的に消す。
   複雑さを足すのは、それ自体が論文の主張であるときだけ。

   test を見て決めた値が主系統に複数入っている:

   | 箇所 | 値 | 何を見て決めたか |
   |---|---|---|
   | 生成サンプリング | `T=0.85`, `top_p=0.95` | 生成物の Vina |
   | refiner | 反復 3 回, `λ_bond≈10` | 生成物の Vina / PB |
   | ポケット緩和 | `contact-scale 1.10–1.15`, `w-internal 100` 他 | test 100 標的のうち 25 標的の Vina |
   | 棄却サンプリング | プール 400/800/1150, サイズ下限 0.8× | 生成物の vina_dock |
   | pose ヘッド | 56 本から最良を選択 | CASF の DP |
   | pose スコア | 3-head + Vina の z-sum | CASF の DP |
   | 親和性 | 5 モデル固定アンサンブル (LF5) | CASF の R / ρ |

   - ハイパラは **既定値のまま使う** か **検証集合で決める** のどちらか。
     「なぜ 0.85 なのか」に一行で答えられない値を主系統に置かない。
   - 主表は単一モデル。アンサンブルと物理との融合は ablation 側に置き、増分として報告する。
   - 「一番単純な構成にしたら何点落ちるか」は聞かれる前に自分で測って載せる。
   - ヘッドも最も単純なもの（mean-pool + MLP）を主系統にし、attn / meanmax / pair / listwise は
     ablation にする。主系統が単純なほど、トークナイザの寄与という主張が素直に読める。
   - **分析にも適用する。** 出発点は `T=0.85` 込みではなく既定ハイパラの最小構成で測る。
     そうしないと改善量がチューニング分と混ざる。
