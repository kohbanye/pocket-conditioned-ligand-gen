# 【撤回】芳香性ヘッドは崩壊していなかった (2026-08-22 訂正)

**この文書が元々主張していた「トークナイザの芳香性ヘッドが再現率 0.014 で
崩壊している」は誤りだった。原因は測定スクリプトのバグ。**

## 何が間違っていたか

round-trip の記述子を組むとき、結合次数をこう渡していた:

```python
bonds = [(i, j, int(b.GetBondTypeAsDouble())) for b in mol.GetBonds()]
```

RDKit の `GetBondTypeAsDouble()` は**芳香族結合に 1.5 を返す**。`int()` はこれを
**1** にする。つまり全ての芳香環が単結合だけの環として記述子に渡っていた。
`LigandAtomDescriptor.compute` はその結合次数から RDKit mol を組み立てて
`atom.GetIsAromatic()` を読むので、記述子は当然「非芳香族」と言う。

**モデルは非芳香族の分子を正しく非芳香族と答えていた。**それを RDKit の
真の芳香性と突き合わせて「再現率 0.014」と報告していた。

## Kekulize してから測り直した結果

| | 誤った測定 | 正しい測定 |
|---|---|---|
| 芳香性 再現率 | 0.014 | **0.960** |
| 芳香性 適合率 | 0.833 | **0.988** |
| 芳香性 一致率 | 0.695 | **0.984** |
| numH 正解率 | 0.716 | **0.978** |
| element 正解率 (対照) | 0.992 | 0.993 |

**ヘッドは極めて正確**。`_constrained` の乗数が 0 のままだったのも当然で、
制約は満たされていた。

## 対照を取っていたのに読み違えた

element 0.992 を見て「記述子は正しい」と結論したが、**element は結合次数に
依存しない**。結合次数に依存する numH が 0.716 と中途半端だったのが手がかり
だったのに、そこを追わなかった。**対照は「何に依存しないか」まで見て選ぶ。**

## この誤診の上に立てたもの

- `--freeze-encoder` / `--balanced-chem-loss` / `--init-from` の実装
- デコーダ単独 fine-tune 3 本 (`vq_decoder_arom`, `_hw`, `_ctrl`, `_srcbal`)

いずれも**存在しない問題**を狙っていた。ただし副産物として得たものは残る:

- **デコーダ単独学習でコードが動かないことの実証** (参照リガンド 100/100 で
  コード完全一致、`transformer_encoder` の重み変化 0.0000e+00)。将来
  デコーダだけ直したくなったときに使える。
- `_class_balance` は正しく動く (崩壊した予測器の損失を 1.59 倍にする) ことを
  単体で確認済み。使う場面が来れば使える。

## 生成分子の芳香性不足そのものは実在する

これは生成 SDF から直接測ったもので、上のバグの影響を受けない:

| | 参照 | 生成 |
|---|---|---|
| 芳香族原子の割合 | 0.295 | **0.194** |
| 芳香族原子ゼロの分子 | 0.340 | **0.596** |

トークナイザは正確なので、**不足は LM 側**。ただし **Vina の観点では優先度が
低い**: dock (ポーズを捨てた純粋な分子の質) は参照に **+0.24** しか負けて
いないのに対し、ポーズは **5.18 kcal/mol** 失っている。Vina は芳香性を
ほとんど報いない。QED / drug-likeness の議論では効くので、そちらで扱う。
