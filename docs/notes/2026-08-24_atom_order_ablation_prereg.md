# 原子順アブレーション: 測る前に予測を書いておく (2026-08-24)

このセッションで 3 回、**測ったあとに解釈を選んで間違えた**:

- アンカー温度を「16% 改善」と報告 -> 後処理の交絡で、正しくは 6%、
  Vina では有意差なし。
- 補助ヘッドを「1.850 に改善」と報告 -> 2k step の揺らぎで、4k では 2.348。
- 「CLM はポケットを見ていない」と報告 -> 重心の下限と最初の原子の誤差を
  比べていた。正しい下限は 3.24 A で、CLM の 2.13 A はそれを上回る。

どれも**結果を見てから何と比べるかを決めた**のが原因。今回は先に書く。

## 設定 (完全に一致させた)

| | file 順 | buried_first 順 |
|---|---|---|
| コーパス | `lm_tokens_abl_file` | `lm_tokens_abl_ord` |
| train / val | **196,839 / 25,632** | **196,839 / 25,632** |
| VQ | `vq_e250_lig3` (ep244) | `vq_e250_ord` (ep248) |
| 除外ポケット | ベンチマーク 93 | 同左 |
| lr / batch / epochs | 3e-4 / 32x2 / 6 | 同左 |

**分離できないもの**: 順序を変えると VQ も変わる。往復 RMSD は
0.365 (file) vs 0.459 A (ord) で **ord が 26% 悪い**。だからこの比較は
「順序 + そのトークナイザ」の効果。順序だけの分離は原理的にできない。

## 予測 (結果を見る前に)

機構の予測は「buried_first では最初の原子が正準な幾何量になるので、
アンカーが予測可能になる」。定数予測の下限は **3.24 -> 1.28 A**。

| 指標 | 予測 | 外れたら |
|---|---|---|
| **アンカー誤差** (teacher forcing, 最初の原子) | **file より小さい。1.28 A の下限に向かって動く** | 機構が違う |
| 全原子の誤差 | ord がやや**悪い** (VQ が 26% 悪いので) | - |
| val loss | **比較不可** (トークン列が違う) | - |
| 生成の重心ずれ | ord が小さい | アンカーが分子に伝播しない |
| Vina score | ord が良い。ただし**小さい** | - |

**Vina で 4 kcal/mol が埋まるとは予測していない。** アンカー改善で
期待できるのは +0.6 kcal/mol 程度、VQ の悪化で -0.3 kcal/mol 程度
(ポーズ精度曲線から)。**差し引き +0.3 前後。**

## 判定の規則 (先に決める)

- 主要指標は **アンカー誤差の対応のある差** (標的ごと、Wilcoxon)。
  中央値だけでは判定しない (補助ヘッドで踏んだ罠)。
- **同じ学習ステップ数の checkpoint 同士**で比べる。片方だけ進んだ
  状態で比べない。
- Vina は**同じ後処理段階**で比べる (`_post` 同士)。
- 有意でなければ「効かなかった」と書く。中央値が動いていても。

## 結果 (epoch 1、途中経過)

同一コーパス (196,839 doc)・同一設定・同一 epoch:

| | アンカー中央 | 平均 | 完全一致 | NLL | 全原子中央 |
|---|---|---|---|---|---|
| file 順 | 2.484 | 2.693 | 0.000 | 9.34 | **1.876** |
| buried_first 順 | 2.412 | 2.636 | 0.000 | 9.58 | **3.344** |
| (定数予測の下限) file | 3.24 | | | | |
| (定数予測の下限) ord | **1.28** | | | | |

### 主要指標: 差なし

対応差 (ord - file) 中央 **+0.063 A**、ord が良い標的 **49%**、**p=0.97**。

**下限が 3.24 -> 1.28 A に下がっているのに、モデルはそれを取りに行って
いない。** 予測は支持されない。

### 副次指標: 予測より遥かに悪い

「ord がやや悪い」と予測したが、実際は全原子誤差
**1.876 -> 3.344 A (+78%、p=4.6e-108)**。VQ の 26% 劣化では説明できない。

### ただし両方とも学習不足

完全一致 **0.000**、NLL 9.3-9.6。配備モデル (アンカー 2.25 A、NLL 7.99、
完全一致 0.013) に遠く及ばない。epoch 1/6 で、197k doc は
配備コーパス (16.5M) の 1.2%。

**この時点の判定は早い可能性がある。** 事前に決めた「同じステップ数で
比べる」規則には従っているが、**両方とも実力が出ていない段階の比較**
であることは結果と一緒に書く。epoch を進めて再測する。

## 最終結果 (学習完了、epoch 2 同士)

| | アンカー中央 | 完全一致 | NLL | 全原子中央 |
|---|---|---|---|---|
| file 順 | **2.390** | 0.013 | 9.35 | **1.832** |
| buried_first 順 | 2.688 | 0.000 | 9.69 | 3.448 |
| (定数の下限) file | 3.24 | | | |
| (定数の下限) ord | **1.28** | | | |

- **主要指標: 差なし** — 対応差 +0.059 A、ord が良い標的 49%、**p=0.65**
- **副次指標: 予測の逆** — 「やや悪い」と書いたが実際は **+88%** (1.83 -> 3.45)

## 却下

**「アンカーが正準な幾何量になれば予測しやすくなる」機構は、
モデルの学習では実現しない。** 定数予測の下限が下がることと、
モデルがその下限に近づくことは別問題だった。

さらに buried_first は全原子の誤差を 88% 悪化させる。VQ の往復劣化
(0.365 -> 0.459 A、26%) だけでは説明できない大きさで、**原子順そのものが
系列モデルにとって難しくなっている**と考えるのが自然。file 順 (SDF が
書いた順) は、少なくとも「化学的に自然な描き順」であることが多い。

## 事前登録の効用

予測を先に書かなければ、**「ord は val loss が良い (6.0999 vs 6.1392)」と
報告していた可能性が高い**。だが val loss はトークン列が違うので比較不可と
先に決めてあり、実際に測ったアンカー誤差では ord の方が**悪い**
(2.688 vs 2.390)。

このセッションで同じ罠を 4 回踏んだ (アンカー温度・補助ヘッド・
ポケット非依存の基準・今回)。**結果を見てから何と比べるかを決めない。**
