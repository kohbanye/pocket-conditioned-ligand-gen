# 【撤回】押し込み腐敗は効かなかった (2026-08-25 訂正)

**この文書が主張していた「press0.6 が改善を 1.6 倍にする (p=0.008)」は
epoch 0 の checkpoint 同士の比較で、学習を進めると消える。**

各腕を**自分の val 最良 checkpoint** (配備時に選ぶのはこれ) で測り直した
結果 (100 標的、`docs/results/refjud2_*.json`):

| 腕 | start との差 | 改善標的 | p |
|---|---|---|---|
| **`refit_deploy` (押し込み無し)** | **-0.865** | 65.7% | 3.3e-05 |
| `refit_press0.6` | -0.731 | 66.7% | 6.4e-06 |
| `refit_press0.4` | -0.514 | 64.6% | 8.6e-05 |
| `refit_press0.9` | -0.441 | 57.6% | 0.0067 |
| `refit_press1.3` | -0.289 | 53.5% | 0.013 |

直接対決 (対応のある差):

| | Vina score | RMSD |
|---|---|---|
| deploy vs press0.6 | +0.134 (p=**0.267**) | **-0.054** (67%, p=1.1e-05) |
| deploy vs press0.4 | +0.001 (p=0.996) | **-0.062** (71%, p=1.1e-06) |

**Vina では引き分け。幾何では deploy が勝つ。**
しかも「結晶に近づけたか」で見ると、有意に近づけているのは deploy だけ
(-0.063、65%、p=3.9e-05)。press0.4/0.6 は有意でなく (p=0.84 / 0.32)、
press0.9/1.3 は**遠ざける** (+0.029 / +0.053)。

**sigma を上げる方向が間違っていた。**押し込みは配備時の誤差の主成分ではない
(主成分は内部変形。`2026-08-25_the_corruption_had_the_wrong_shape.md`)。

## なぜ間違えたか

**epoch 0 の数字を結論として報告した。**「補助ヘッドが 2k step で改善」を
4k step で取り消したのと同じ罠で、今回が 5 回目。
`docs/notes/2026-08-24_atom_order_ablation_prereg.md` に
「同じ学習ステップ数の checkpoint 同士で比べる」と書いてあり、epoch 0 同士は
その規則を満たしていた。**足りなかったのは「両方とも実力が出ている段階か」**
という条件のほう。ablation ノートには実際にそう書いてあったのに、
press では書かなかった。

さらに、判定をやり直した最初の試みは**別のバグで無効**だった:
`refiner_on_known_error.py` が checkpoint 名を `parent.parent.name` から
作っていたので、`_pinned/` に並べた 5 本が全部同じ名前に潰れ、
dict は最後の 1 本だけを残して 5 本ぶんに見えるラベルで報告していた。

## 残るもの

`rigid` 単独が**悪化させる** (+0.533、改善標的 39.4%、p=0.67) という測定は
生きている。数値最適化は配備時の誤差に効いていない。

# 押し込み腐敗でリファイナが 1.6 倍効くようになった (2026-08-24)

**公平性の制約内 (学習モデルのみ) での、このセッション最大の改善。**

## 何を変えたか

リファイナの学習時の腐敗は等方だった:

```python
x0 = x0 + rng.normal(0.0, rigid_trans, 3)   # 方向の偏りなし
```

だが実測の誤差には方向がある。**生成ポーズは受容体側へ一様に深い。**
`--online-press-sigma` を足し、ポケットの重心へ向かって `|N(0,s)|` A
押し込む腐敗を加えた。

検証 (val 250 例、ポケット重心方向への変位):

| | 中央 | 正の割合 |
|---|---|---|
| 現行 (等方のみ) | -0.071 A | **47%** (コイントス) |
| press 0.4 | +0.483 A | 61% |
| 実測の生成ポーズ | +0.363 A | — |

## 結果 (100 標的、配備時と同じ誤差)

| 腕 | score | 出発点からの改善 | 改善標的 | p |
|---|---|---|---|---|
| 出発点 (CLM argmax) | -1.78 | — | — | — |
| **`rigid` のみ (数値最適化)** | **-1.33** | **+0.53 悪化** | **39%** | **0.67** |
| `refit_deploy` (既存 ML) | -2.59 | -0.87 | 66% | 3.3e-05 |
| **`refit_press0.4`** | -2.71 | **-1.18** | 71% | 1.0e-07 |
| **`refit_press0.6`** | **-2.86** | **-1.40** | **73%** | **1.5e-08** |

直接対決 (vs `refit_deploy`):

| | press が良い標的 | p |
|---|---|---|
| press0.4 | 59% | 0.047 |
| press0.6 | **64%** | **0.008** |

**改善幅が -0.87 -> -1.40 kcal/mol、1.6 倍。しかもまだ epoch 0。**

## 数値最適化は配備時の誤差に効いていない

`rigid` 単独は**悪化させる** (+0.53、改善標的 39%、p=0.67)。
`rigid+ref` も `ref` 単独に劣る (-1.00 vs -1.40)。

**公平性のために外すのではなく、外したほうが良い。** これは
`gen100_arom_post` で見えていた「place_first が効く」と矛盾するように
見えるが、あちらは**後処理 (MMFF/ねじれ) と組んだ状態**の話で、
配備時の誤差そのものに対しては効いていない。
