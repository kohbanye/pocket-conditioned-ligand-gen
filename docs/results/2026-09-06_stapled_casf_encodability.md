# 貼り合わせベースラインは CASF-2016 の 96.5% を符号化できる

日付: 2026-09-06 / 測定: `benchmarks/pose-rescoring-bench` のエンコーダ半分のみ
(GPU 不要、ヘッドもMLMも通していない)。スコアを一つも出す前に、
ベースラインの**到達範囲**を先に測っておくためのもの。

## 結果

| | 件数 |
|---|---|
| pocket setup 成功 | **285 / 285** (ESM3 キャッシュは全ターゲットに当たる) |
| 3 ポーズ以上を符号化できたターゲット (= 実際に採点される) | **275 / 285 = 96.5%** |
| 符号化できたポーズ | **21,345 / 22,492 = 94.9%** |
| 全ポーズ符号化 | 263 ターゲット |
| 一部だけ符号化 | 12 ターゲット |

## 落ちた 10 件は「全部か無か」

0/100, 0/94, 0/90, 0/60, 0/89, 0/98, 0/100, 0/100, 0/100, 0/72。
**部分的に落ちたものが一つも無い**。これはポーズの問題ではなく分子の問題という
合図で (`feedback_measurement_traps` の「0% か 100% は入力を疑う」の逆向きの
使い方: ここでは入力ではなく**分子レベルの失敗**だと分かる)、実際に理由を
引くと分子ごとに一意に決まる:

| 理由 | 件数 | ターゲット |
|---|---|---|
| ConfSeq が書けない | 8 | 2y5h, 3b68, 3jvs, 3oe4, 3oe5, 3ozs, 3ozt, 4dld |
| RDKit の kekulize 失敗 | 2 | 1lpg (41 heavy), 3arp (34 heavy) |

前者はベースラインの真の限界で、論文に書く。後者は mol2 が芳香族結合 (type 4)
として書いた環に Kekulé 構造が付かない場合で、`heavy_atom_mol` の緩和フォールバックが
valence チェックだけを外し kekulize は残しているために落ちる。

**kekulize まで外すことはしない。** 一度「自分のコードが厳しすぎた」で 15% を
失っており、その反省で valence は既に外してある。だが kekulize を外すと
芳香族認識が矛盾したままの分子を ConfSeq に渡すことになり、出てくる SMILES が
正しい保証が無い。**ベースラインを 0.7% 助けるために、間違った分子を通す方が
悪い。** 2/285 は理由付きで報告する。
