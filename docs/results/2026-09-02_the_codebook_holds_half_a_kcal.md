# 往復誤差の 42% はコードブックの粒度で、それは 0.54 kcal である

2026-09-02、olab-ws4。正典 100、配備 VQ。**同じ潜在を 2 通りに復号**して、
往復誤差をコードブックの粒度とデコーダ自身の限界に分けた
(`quantisation_vs_decoder.py`、`TransformerVQVAE.encode_to_latent` /
`decode_from_latent` を追加して迂回路を作った)。

## 測定

| | 往復 RMSD |
|---|---|
| **コードブック経由**（配備経路） | **0.3502 Å** |
| **コードブック迂回**（デコーダの床） | **0.1868 Å** |
| **差** | **+0.1469 Å** |

潜在空間の量子化誤差は潜在ノルムの **18.4%**（4.957 / 27.018）。

0.3502 Å は同日の天井測定 (`2026-09-02_the_tokenizer_costs_0.78_kcal.md`) の
0.350 Å と一致する。**別経路で同じ値が出たので、この迂回路は正しい**。

## kcal に直す

交換レート **3.69 kcal / Å**（同日測定）は差分に当てるのが正しい
（当てはめの切片 −0.30 があるので絶対値には使わない）:

**コードブックを理想化すると 0.1469 Å × 3.69 = 0.54 kcal 戻る。**

| | 天井 |
|---|---|
| 現在（往復 0.350 Å） | **−5.582** |
| コードブック理想（往復 0.187 Å） | **約 −6.1**（三分位の外挿では −6.4 付近） |
| FLOWR（記録） | −5.700 |

**リファイナを足さずに FLOWR を超える。** 現在は天井そのものが FLOWR と
ほぼ同着で、リファイナ込みでようやく 0.2 kcal 上回る位置にいる。

## これは何を許可し、何を許可しないか

- **許可する**: residual VQ / コードブック拡大。**上限 0.54 kcal が測れている**ので、
  GPU を払う前に期待値が分かる。0.1469 Å は「無限のコード」の値なので、
  2 段の residual VQ が取るのはその一部である。
- **許可しない**: 「デコーダを大きくすれば良い」。デコーダの床 0.1868 Å は
  往復誤差の過半（RMSD で 53%）だが、**これは別の軸**で、
  コードブックを増やしても 1 Å も動かない。逆も同じ。
- **注意**: `2026-08-23_tokenizer_ceiling.md` は「トークナイザの作り直し
  (residual VQ 等) は後回しでよい。天井は律速ではない」と書いた。
  律速ではないのは正しいが、**余裕は 0.2 kcal しかなく、
  そのうち 0.54 kcal が手つかずで置いてある**。

## 走行中の腕との関係

`buried_first` は往復 RMSD を 0.35 → 0.44〜0.48 Å に**悪化させる**予測で、
その代償は 0.33〜0.48 kcal（改訂した中止閾値 0.486 Å はここから来ている）。
**コードブックが持っている 0.54 kcal は、その代償をちょうど払える大きさ**である。
2 つは直交する（原子順と量子化粒度）ので、**組み合わせれば
buried_first の代償を消せる**可能性がある。

## 次に測ること

**residual VQ の 2 段目が 0.1469 Å のどれだけを取るか。** 上限は測れたので、
残るのは効率だけである。1 段目の残差 (z − lookup(code)) の分布を見れば、
2 段目に何個のコードが要るかは学習前に見積もれる。
