# LM を差し替えても誤差は減らない (2026-08-25)

配備しているのは `clm_e250lig3_fullft/lm-e00-vl5.3568.ckpt`、**epoch 0 の重み**。
それより長く / さらに finetune した checkpoint が 2 つあるので、
teacher-forced argmax の誤差を同じ 100 標的・同じ分子で測った
(`refiner_on_known_error.py --source clm`)。

## 結果 (標的で対応をとる。中央値の引き算では判定しない)

| | 生の RMSD | 生の score | 生の min |
|---|---|---|---|
| `fullft` e00 (現行) | **1.902** | **-1.784** | -3.935 |
| `nnft` e00 | 2.030 | -1.722 | **-4.364** |
| `clean` e02 | 2.175 | -1.227 | -4.044 |

対応のある差 (負なら fullft より良い):

| | vs fullft の RMSD 差 | fullft より良い標的 | p |
|---|---|---|---|
| `nnft` | **+0.098** | 41.0% | 0.014 |
| `clean` | **+0.220** | 34.0% | 0.00062 |

**どちらも fullft より悪い。**score の差はどれも有意でない
(p=0.30 / 0.059)。`nnft` はリファイナ後の score が -0.247 良いが p=0.335。

## 読み

**checkpoint の選択は既に正しい。**val loss が低い (3.55 対 5.36) のは
コーパスが違うからで、比較になっていなかった。ポーズ誤差で測ると逆。

LM 側のレバーは「もっと学習する」ではない。**損失関数のほう**。
コードブック上の交差エントロピーは、どの誤答も等しく誤りとして扱う。
しかしコードは記号ではなく**場所**で、`code_mean_coords` の表がそれを持っている
(コード間の最近傍距離 中央 0.29 A、32 番目で 1.04 A)。

量子化だけなら原子は結晶から 0.35 A、LM の argmax を通すと 2.52 A。
**ずれのほとんどは「幾何的に遠いコードを選ぶ」ことで生まれていて、
学習に使った損失はその区別を見ていない。**

実装: `--code-geometry-tau`。真のコードの近傍にガウス重みを置いた
soft target にする (`tests/test_code_geometry_ce.py` が
「近い外し < 遠い外し」を固定)。

## 副産物のバグ

`refiner_on_known_error.py` は checkpoint 名を `parent.parent.name` から
作っていた。`_pinned/` に並べた 5 本が**すべて同じ名前に潰れ**、dict は
最後の 1 本だけを残して、5 本ぶんに見えるラベルで報告していた。
名前が衝突したらエラーにするよう修正。**エラーで落ちるほうが、
もっともらしい 1 本の結果より良い。**
