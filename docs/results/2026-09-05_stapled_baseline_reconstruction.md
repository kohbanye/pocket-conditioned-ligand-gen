- jobs `8575773` (`pbstap`, gpu_1) / `8575774` (`pbown`, gpu_1)
- `benchmarks/recon-bench/results/posebusters_stapled.parquet` (6420 行) と
  `posebusters_ownbb.parquet` (2140 行)
- 検定: 対応あり Wilcoxon + paired bootstrap CI + Holm 補正
  (`prolit_bench.stats`)、n=428 (界面リガンド RMSD のみ n=385)

## 何を測ったか

論文への最も自然な反論——**「タンパク質専用トークナイザとリガンド専用
トークナイザを貼り合わせれば済むのでは」**——に数字で答える。

baseline は **ESM3 structure tokenizer × ConfSeq**。各モダリティで
この同じベンチの再構成が最良の組み合わせで、しかも ConfSeq は
**リガンド化学で ProLIT に勝っている** (下表)。弱い相手ではない。

どちらも SE(3) 不変でリガンドの配置を持たないので、欠けている剛体変換を
**明示的なポーズトークンとして与えた**。予算は 0 / 13 / 26 / 39 ビットと
oracle (真の変換を無償で渡す、実現不可能な上限)。

**スコープ**: ESM3 は backbone (N/CA/C) しか復元しないので、界面指標は
**両アームとも backbone 限定**で計算した (ProLIT 側に `complex_backbone`
行を新設)。ProLIT の all-atom 界面値と直接並べていない。

## 読み

### 1. ポーズ予算は 3 トークンで飽和する。そして飽和しても届かない

39 ビット (3 トークン) と oracle の差は lDDT-PLI で 0.007 しかない。
**配置の情報はもう十分渡してある。** それでも oracle ですら ProLIT に
lDDT-PLI で 0.107、Contact-F1 で 0.131 負ける (どちらも Holm p < 1e-13)。

当初の予想は「break-even に必要なビット数」を出すことだった。**予想は外れた。
break-even は存在しない**——真の剛体変換を無償で渡しても届かない。

### 2. なぜか: 2 つのデコーダの誤差が独立だから

貼り合わせ構成では、ポケットは ESM3 が (backbone Kabsch 1.361 Å、lDDT 0.910)、
リガンドは ConfSeq が (Kabsch 0.607 Å) **それぞれ独立に**復元する。
2 つの誤差を結びつけるものが列の中に何も無いので、正しい配置を与えても
界面の相対幾何は両者の誤差の**和**になる。

ProLIT は同じポケット正準フレームの球面座標として両方を 1 つの表現から復号する
(backbone Kabsch 0.264 Å、lDDT 0.995)。誤差が共通のフレームを通るので相関する。

これは**「共有フレームは配置ビットを節約する」より強い主張**である:
共有フレームは、配置を無償で運ぶだけでなく、**2 つのモダリティの復元誤差を
結合させる**。

### 3. 貼り合わせ側が勝っている所は正直に書く

| 指標 | ProLIT | ESM3+ConfSeq | 勝者 |
|---|---:|---:|---|
| リガンド結合長 MAE (Å) | 0.122 | **0.040** | ConfSeq |
| リガンド結合角 MAE (°) | 10.08 | **2.27** | ConfSeq |
| リガンド Kabsch (Å) | **0.486** | 0.607 | ProLIT |
| **界面 lig RMSD (39bit/oracle)** | 0.558 | 0.73 / 0.64 | **有意差なし** |

**正しい配置さえ与えれば、リガンドの界面原子の位置は互角**である
(Holm p=0.30)。負けているのはポケット側と接触パターンであって、
リガンド自身の幾何ではない。ConfSeq は内部化学で明確に上回る。

### 4. レート

ProLIT は **3,276 ビット**でこれを達成し、貼り合わせ構成は
**7,118〜7,157 ビット**を使って届かない。2.2 倍のビットを使って負けている。

⚠️ ビットの数え方は明示が必要: ESM3 のトークンは**全鎖**分を計上している
(ポケットだけ符号化させると backbone Kabsch が 0.30 → 8.48 Å に崩れるので、
全鎖符号化が ESM3 にとっての正しい使い方であり、そのコストを払うべき)。
ポケット残基分だけ (約 30 トークン) を計上すれば baseline のビットは大きく
下がるが、その場合の再構成品質は測っていない値になる。**表には両方を
書くか、この脚注を必ず付ける。**

## 論文への反映

- Table 1 に `ESM3 + ConfSeq (+ N bit pose)` 行群を追加。oracle 行を
  「実現不可能な上限」として明示
- 主張は「共有語彙は配置を無償で運ぶ」から
  **「共有フレームは 2 つのモダリティの復元誤差を結合させる。独立な
  トークナイザ 2 本では、配置を無償で与えても界面は再現できない」**へ
- ConfSeq が結合長・結合角で勝っている事実を Limitations に書く。
  これは `2026-09-05_posebusters.md` の「リガンド化学で ConfSeq に負ける」
  と同じ話で、隠すと矛盾する
